# Architecture decision records

Architecture decision records (ADRs) capture durable decisions that change a
system boundary, data invariant, security posture, deployment contract, or
operator responsibility.

Use the next four-digit number and a short kebab-case title, for example
`0001-agent-action-authority.md`. Each ADR must include status, context,
decision, alternatives, consequences, migration/rollback impact, and links to
the implementation and verification evidence. Accepted ADRs are append-only;
supersede them with a new ADR instead of rewriting their history.
